## 判定约定

2026-10-29 用户授权对照本地 Sketch/Figma 逆向资料评估模糊无需逐位精确。[画布模糊迭代](../testing/verification-canvas-blur-20261029/README.md)据此对限定 SDR WebGPU 画布累加采用预先冻结的误差门（黑/白底合成后最大未量化编码误差与 alpha 误差均 < 1/255），不再要求该显示层与旧有理累加逐位一致。原核、半径、支撑、四相、分条、内存、HDR/显式精确输出及文档语义仍保留；其它 G3 要求不变。该例外不授权降低画布分辨率，也不把算子或指定视口收益当成 33/100ms 或全 G2/G5 验收。

- 每个门只有 PASS、FAIL、BLOCKED、NOT_RUN、NOT_APPLICABLE 五种状态。PASS 必须同时有指定输入、实际运行命令、退出码、日志和本门要求的观测证据。BLOCKED 是缺少环境/样本/oracle/阈值；NOT_RUN 是尚未执行；两者都不是通过。
- NOT_APPLICABLE 须写明变更范围和理由；不能用于删除固定矩阵、把不支持平台隐藏掉或绕过真实应用门。限定范围开发包可以带未通过项交付，但必须标为候选，不能声称完整渲染验收。
- “渲染体验完成”要求 G0–G8 对声明支持的环境全部通过，G10 交付门通过；G9 功能仅在各自被纳入范围时另行验收。单一修复可先通过对应门，不因此把其余未验门标绿。
- 每条验收记录至少含 gate_id、case_id、status、reason、command、exit_code、run_id、日志/观测文件路径与 SHA-256。预期拒绝用例只有原子拒绝及边界正确才通过；普通场景被拒绝仍是该场景 FAIL。

## G0：渲染 No.1 与变更顺序

当前优先解决：模糊残留、白板/白块、3200% 放大后缩回、快速反向缩放、旋转、拖动、resize、紫色选择框与画布同步，以及连续编辑不冻结。它们是独立问题，修好其中一个不能关闭其余项。

执行门槛：

1. 每个候选关联至少一个可复现故障编号，写下输入、步骤、旧行为、预期行为及 G2/G6 对应 case_id。仅整理结构、添加统计或增加功能，不应被计作渲染修复。
2. 上述故障仍未通过时，发布的关键路径先安排渲染修复、正确性回归和必要证据。新增美术功能可并行做隔离设计/原型，但不得挤占测量资源、改变默认渲染路径或延后已知阻塞修复。
3. 候选在联合基线上重跑所影响的门。分支 A 和 B 各自通过不等于合并后通过；合并冲突、运行时漂移或新配置均使相关旧证据失效。

通过证据：故障清单与本轮变更映射完整；没有用新增功能数量、吞吐或缓存命中率替代交互问题验收。尚有故障可继续交付开发候选，但不得声称全部完成。

## G1：Rust 主逻辑，UI 输入与展示

Rust 是主要领域逻辑与权威语义的承载层：文档有效性、几何/变换、布局、效果与渲染语义、编辑事务/历史、导入导出和持久化一致性通过既有 Rust/WASM/native 边界实现。UI 处理输入、短期交互状态、面板展示与适配，不复制一套文档模型、几何算法、效果语义或业务校验作为最终真相。

这不是“当前每条路径已在 Rust”的事实声明。现有 TS/WebGPU 呈现与平台适配可以保留；每轮迁移应针对实测热路径或语义归一，不为技术比例进行无界重写。

执行门槛：

- 提交调用链与命中证据：真实应用入口 → UI 命令/输入 → 现有 Editor 事务 → 实际 Rust/WASM/native 入口 → 渲染/保存产物。测试专用 Rust 实现、未调用模块或 UI 仍执行旧算法均不能证明迁移生效。
- Rust 修改后重建实际被加载的 WASM 和受影响 native 二进制；记录源码、工具链、锁文件、构建参数与最终文件 hash。只重跑使用陈旧 generated WASM 的前端测试不通过本门。
- 同一操作经 UI 和已存在的自动化入口，比较权威模型/结果与一次撤销重做边界；非法输入和冲突应由权威路径拒绝，不能只依赖 UI 提前检查。
- CPU 密集任务不得转移到 UI 主线程或阻塞异步运行时；跨边界传输测量实际复制字节、序列化时间和等待，防止 Rust 加速被全量往返抵消。

## G2：连续交互与真实可见画面

每个 G5 必测场景均运行同一版本的确定性动作脚本，保留动作序列与随机种子。初始载入/冷缓存、暖缓存交互和停止后的精修分别计时，不可把启动开销隐藏在预热，也不可把停手后的清晰截图当成运动中证据。

动作链至少覆盖：原始视图 → 放大到 3200% → 缩回原视图 → 未等前次结束即反向缩放；正反向平移/拖动；旋转后立刻反转；resize 后继续拖动与旋转；拖动中修改右侧属性；提交、撤销、重做后立即再次编辑。固定脚本还须包含取消、换选择、换页/文档和停止输入后的收敛步骤。

执行门槛：

1. 非透明背景/内容区域不得出现非预期白板、白块、丢层、旧内容覆盖、跳回旧相机或重复合成；清晰度以当前显示层既定质量和独立 oracle 检查，不能任意降低显示分辨率取得帧率。停手后的最终帧达到既有精确层要求。
2. 紫色选择框、控制柄、命中区域、变换面板值与画布内容使用同一有效 document/session/revision/gesture/pose 身份。逐帧检查坐标投影及可见错位，容差在运行前固定；不能仅证明 React 状态相同或同一消息中 ACK。颜色不同的平台以相同选择覆盖层语义验收。
3. 连续编辑期间 UI 可处理输入且呈现跟随最新有效动作，队列不持续积压。沿用[已有诊断定义](CANVAS_FRAME_GRID_DIAGNOSTICS.md)检测大于 250 ms 的 UI 回调停顿：活跃可见编辑窗口内 uiStalls 必须为 0；后台隐藏窗口另列，不当作快样本。该门槛是停顿检测，不等于“250 ms 内像素必到”或物理 FPS 承诺。
4. 输入到真实画面的 P95/最大时间、停止到精确画面的时间、最大旧帧持续时间须满足运行前固定的目标值；另报输入到提交、GPU 完成与 wall 时间。尚无这些目标或缺少真实像素时，本门为 BLOCKED，不能仅凭 UI 回调无停顿通过。
5. 使用真实 GUI 逐帧录制/截帧和对应身份日志定位可见错误；GPU readback 可证明目标纹理像素，不能单独证明 GUI 合成/选择框同帧或显示器 scanout。只有专门输入到光子测量才可声称该物理延迟。

阈值登记必须在运行前固定：设备/平台/DPR/窗口尺寸/刷新率、声明支持范围、上述各延迟目标、几何/像素容差、采样窗口、预热和重复次数。优先采用已有正式目标；缺失时先提出明确数值目标并确认，测试后不得为过关自行抬高。不得预设所有设备都应达到 60/90/120 FPS，也不得把无阈值写成 PASS。

## G3：精度、HDR、导出、持久化不退化

执行门槛：

- 比较当前权威模型中的浮点/HDR authored 值、拓扑、曲线控制柄、变换、字体/排版、裁剪、混合、效果次序和透明度；保存重开、撤销重做与导入导出后仍按现有契约保留。SDR 预览不证明 HDR 显示输出。
- 对同一显示精度层的缓存/传输优化用相应精确 oracle；对精确导出/readback 用原要求的严格比较。必须明确逐字节一致、浮点/像素容差和视觉检查各自适用范围，不能把近似数值称作 exact。
- 保持已有 GPU/CPU 工作集、缓存、单资源、样本数、数学精度、effect guard、资源生命周期和不可信输入限制。不得提高预算、移除 guard、静默省略效果、吞掉错误、强行启用默认关闭候选、采用无声降分辨率/近似或降低 export 精度作为本轮渲染修复。
- 确需修改预算、精度层或独立容量策略时，另列变更及理由并单独批准、单独测量；新配置不与旧配置混作性能 A/B。不能据此声称原配置下的缺陷已修复。
- 持久化必须实际写入并重开目标存储，核对资源、文档、版本、CAS、幂等与失败原子性；mock/内存 roundtrip 不等于物理持久化。进程重启也不等于断电/固件故障已验。

任何数据丢失、精度/效果降级、错误被掩盖或导出/持久化回归，均使本门 FAIL，性能收益不能抵消。

## G4：真实生产 CPU 与证据分层

先记录真实应用主 CPU 的阶段与调用栈：输入/编辑、布局/几何、序列化、场景编译、资源准备、调度/等待、提交等。WASM 未解析索引不得标成已确认 Rust 函数；wall 时间包含等待，不能直接当成主 CPU 算力。

每次比较必须固定来源/产物/配置、输入、设备、预热、样本数与运行顺序；交替或配对 A/B，保留失败和异常值及解释，不选择最快一条当结论。采样器开/关分开，报告采样开销。性能 A/B 期间禁止同机并行重构建、重测试或另一个测量任务，记录 CPU/GPU/内存竞争情况。

证据标签至少同时填写两个维度：

| 维度 | 必填分类 | 能证明的范围 |
| --- | --- | --- |
| 执行路径 | CPU production / CPU isolated / mock / software GPU / hardware GPU，并另标 GUI yes/no | 只证明实际经过的后端与入口；GUI 加软件 GPU 不是硬件 GPU |
| 观测 | CPU samples / wall / input receipt / queue submission ACK / GPU completion / target pixel readback / GUI frames / physical scanout | ACK 不等于完成；完成不等于正确像素；目标像素不等于屏幕同帧；GUI 帧不等于物理 scanout |

真实 117、十份实际导入、固定六格规模场景、小合成四类报告分开。小合成、mock 或 isolated CPU 的收益不能外推为真实 117 全编辑器收益。报告每类绝对值、分布、单位和基线变化；尚未获得实际生产路径命中/瓶颈证据时，结论仅能叫候选假设。

通过门槛：声明的主 CPU 优化在真实生产入口被测到，相关阶段与端到端指标满足预先声明的非退化/改善目标，且 G2/G3 未退化。减少 fence、请求数或 ACK 时间自身不足以通过。

## G5：固定验收矩阵

### 规模与内容

| case_id | 内容 | 必需记录 |
| --- | --- | --- |
| V300、V3000、V20000 | 300、3000、20000 个纯矢量可编辑对象 | 节点计数口径、拓扑、可见比例、种子和 fixture hash |
| E300、E3000、E20000 | 同三档对象规模，固定重效果组合 | blur/backdrop/shadow/blend/clip 等具体效果、嵌套深度、半径、覆盖面积及 fixture hash |
| REAL117 | 用户实际 117 源文件，经真实生产导入入口 | 原文件 hash、导入器/配置、实际节点/资源数；不得手工重建冒充 |
| REAL117x10 | 同一原文件实际导入十份的独立副本 | 十次导入日志、每份源 hash、ID/资源映射、总量、撤销和保存重开结果 |
| ICON100 | 固定 100 个图标，修改前后 × 1/2/3 倍导出 | 图标 ID、修改清单、尺寸、导出设置、单图像素 oracle/metadata |

规模场景不是把同一个轻量节点重复若干次就称作通用压力证明：两类生成器和重效果参数须冻结，可见/离屏布局均保留。资源不足或被容量/效果 guard 正确拒绝时，应把拒绝原因记录为普通场景 FAIL/BLOCKED，不能降低对象数量、半径或画布大小后沿用原 case_id。

REAL117x10 必须经过实际 append/import 操作产生十个独立可编辑副本，核对引用不串改、原始快照不变、跨副本修改隔离；不可把一个合成文件、十次空导入或仅复制 JSON 列表叫真实十份验收。样本不可用则 BLOCKED，不用小合成替代。节点数以冻结原文件及实际导入结构推导，不把某次历史计数永久写死。

### 每格操作与输出

- V/E 六格、REAL117、REAL117x10：载入、G2 完整动作链、实际修改、撤销重做、保存重开与导出；冷/暖运行分别留证。
- ICON100：100 个不同 ID 的图标在修改前分别 1/2/3 倍导出；对每个图标执行版本化且可核对的修改，再各导出 1/2/3 倍，共 600 个可追踪图像结果。批量打包可用一个归档，但不得只检查归档存在或挑选几张图。
- 修改后的每个导出核对当前 revision、尺寸/缩放/裁剪/透明度/颜色/效果和实际变化，排除导出旧缓存。检查取消、部分失败、重试及同名冲突的结果清单，不能吞掉丢图。
- 每格分别列 CPU correctness、software GPU、hardware GPU、GUI/persistence 和性能状态。整行全绿须具备声明需要的全部层级；未执行层级保留原状。

## G6：来源、构建、配置与真实 oracle

每次运行绑定以下内容，缺一不能形成可复现 PASS：

1. 输入：源文件/fixture、生成器、动作脚本、随机种子、oracle 与参考图的 SHA-256；用户私有样本用权限合适的内部路径/摘要，不在公开包中擅自附样本。
2. 来源：精确 commit 或源码逐文件 hash 清单及稳定 tree digest；基线与候选分开。无 Git 工作树时不能虚构 commit。
3. 构建：工具链、锁文件、target/profile、构建参数、构建命令、被实际加载的 JS/WASM/native 二进制 hash、应用版本及加载来源。源码 hash 不等于运行时二进制证明。
4. 配置：所有影响结果的环境变量/实验开关、实际预算、渲染后端/adapter/driver、OS、DPR、窗口尺寸、字体/资源集和并发设置；不记录凭据。
5. 测试：精确命令、开始/结束时间、退出码、样本数、真实执行/skip/todo 数、原始日志、录制/像素/trace 的 hash 与失败摘要。运行前后核对源码与产物未漂移。

真实 oracle 必须独立于待改算法的同一错误来源：几何/数学可用已验证解析解或独立参考实现；像素可用经校验参考渲染器/已批准金图；导入含已知错误时不能拿旧错误截图当真值。金图生成不能无检查地从候选自我批准。记录 oracle 来源、版本、容差与适用精度层。

每个声称修复的回归至少建立“旧基线失败、新候选通过”的同输入用例；旧失败须落在预期错误断言，而非依赖缺失、构建损坏、测试不兼容或未进入代码。测试要穿过实际改变路径，并用旧行为/故障注入负对照证明断言有效。真实硬件/GUI缺失时仍可交付 CPU 回归，但保留相应未验状态。

## G7：取消、晚回、资源压力与错误边界

固定故障注入矩阵：排队中取消、准备中取消、提交前取消、提交后取消；乱序/重复/丢失响应；结束/取消手势后的晚回；换页/换文档/换 session/销毁后的晚回；device loss、队列拒绝、分配失败、缓存/工作集压力和重建恢复。

执行门槛：

- 最新有效输入可继续推进；旧 document/session/revision/gesture/pose 结果不得覆盖当前画布或选择框，也不得再次提交已取消编辑。提交后取消不得谎称已回滚，须核对实际提交状态。
- admission、资源持有/释放、在途数量/字节和暂存内存均有既定上界；记录峰值和清退后稳定值。压力循环不应产生持续增长的未归还资源、悬空引用或重复释放。不得通过抬上限掩盖泄漏。
- queue submit/ACK 不是 GPU 完成边界。资源实际完成前保留正确所有权与账本；逻辑退休、物理可回收和已释放分别观测。
- 延迟错误与失败回退保持现有精度及事务原子性，不静默吞掉 fatal、用陈旧帧伪装成功或把 fallback 等同于原路径已恢复。每次恢复后继续真实编辑/导出验证，而非只检查无异常。
- 注入脚本含暂停/释放时序及可重复种子，并覆盖界限内、刚到界限、刚超界限。超界请求按契约有界失败，活动文档/历史/存储保持一致。

通过证据：上述 case_id 与预期结果逐项对应，峰值/泄漏/晚回覆盖/事务断言通过；不能只报测试总数。

## G8：协作可扩展边界不阻塞热路径

为未来协作保留清晰接口，不在当前任务中擅自引入云账户、协作服务或第二套文档真相。

- 稳定身份：document/session/node/resource ID 不以数组下标或 UI 位置替代；副本与资源引用按既有规则映射。
- 操作契约：operation_id 与有界 payload、expected revision、schema/format/capability 版本分开；明确适用文档、原子提交和冲突结果。
- 幂等：相同身份/相同内容重试不重复修改；相同身份/不同内容拒绝；响应丢失后对账或精确重试，不生成新身份盲发。版本冲突不得静默覆盖。
- 快照/增量：快照不可变，增量绑定 base revision/hash 与连续性；缺口、乱序、重复、重放、版本不支持均有明确结果；回放后与权威快照语义一致。
- 热路径：网络、持久化、全量快照序列化和重放不在每帧输入/渲染关键路径同步等待。队列、批次和在途字节有界，背压不丢失已承诺的持久化语义；持久化 CAS 与编辑 revision 不混用。

通过门槛：用真实既有入口测试重复/冲突/丢响应/快照+增量恢复和 UI 连续交互；比较开启与关闭相关接口负载时的主线程与 G2 指标，仍满足冻结目标。仅定义字段不等于已实现协作，未接入网络不能声称多人协作可用。

## G10：增量交付与回滚

每个增量只包含新增/变化实现、相关测试及必要的 Skill/规范/证据，避免重打无关完整仓库。新增文档本身可以构成文档增量，但必须明确“仅规范，未修改运行时”。空变更不得包装成完成。

交付门槛：

1. 发布前冻结来源与产物，生成逐文件新增/修改/删除清单。修改/删除文件列精确旧 SHA-256，新文件要求目标路径不存在；列出精确前置包/基线 digest、应用顺序及依赖，不用“最新版本”作前置条件。

3. 回滚只撤销本包且验证当前新 hash；新增文件仅在内容仍等于本包时删除，修改文件从校验备份恢复。用户后续改动不得强行覆盖；持久化迁移若不可简单回退，必须单独说明。
4. 校验归档路径、清单、非空内容、压缩包与文件 hash、Skill frontmatter、Markdown 相对链接；在隔离目录演练正确前置应用、错误前置拒绝与回滚。不得修改已发包或把后续新增证据偷偷补入原包。
5. 证据区分原包历史通过、当前组合实际重跑、仅静态检查和未验项目；说明 CPU/mock/software GPU/GUI/hardware GPU、真实 117/十份/大规模、性能/像素/持久化各边界。不执行的测试不写通过，存在失败不改名抹去。

交付摘要固定回答：变更是什么；精确前置是什么；本轮实际执行哪些检查；仍有什么失败/未验；如何应用与回滚。默认关闭候选在相应真实联合门通过前仍保持关闭。
